# Box86 16K-page support for Raspberry Pi 5

This fork carries a reproducible Box86 patch/package for running 32-bit i386 ELF programs on Raspberry Pi 5 systems using a 16 KiB kernel page size.

The patch series is based on upstream Box86 commit `0579f8b9c47d87d700724f4cce559b06cbd2b0f5` and ports the newer non-4K ELF32 behavior from Box64/Box32 back to Box86.

## Reproduced failure

```text
host page size: 16384
Illegal Opcode 0x309e9f8a: FF FF FF FF FF FF
```

The same address and bytes were reproduced with both `BOX86_DYNAREC=0` and `BOX86_DYNAREC=1`, placing the fault below the dynarec/interpreter split.

## Patch set

- `patches/16k/0001-elfloader-non4k-host-pages.patch`
  - preserves guest-visible 4K-aligned ELF addresses while backing them with host-page-aligned mappings;
  - maps unaligned PT_LOAD segments when virtual/file offsets share the same host-page offset;
  - handles several 4K ELF segments sharing one 16K host page;
  - defers final host-page protection until every PT_LOAD has been populated.
- `patches/16k/0002-mprotect-4k-guest-on-large-host.patch`
  - accepts normal 4K i386 guest `mprotect()` boundaries;
  - rounds actual host calls to the host page size;
  - preserves permissions needed by neighboring guest sub-pages;
  - keeps Box86 protection/dynarec tracking synchronized.
- `patches/16k/0003-rpi5-arm64-build-profile.patch`
  - adds `RPI5ARM64` using the armhf cross compiler on an aarch64 Pi 5 and tunes for Cortex-A76.

The loader logic is derived from the mature non-4K Box32 implementation in Box64, notably Box64 commits `61d01a4c2c7220b57952b83c270df3f058180095`, `b5d45778c437961a3d7042a680acf33d980f05ff`, and the large-host-page protection work in `9c11c5671c6d385357321856ff75894afab4ee5f`.

## Build an armhf Debian package

On Debian 13 / Raspberry Pi OS arm64:

```bash
./scripts/install-box86-16k-build-deps-debian13.sh
./scripts/build-box86-16k-deb.sh
```

The builder creates a clean worktree at the pinned upstream commit, applies `patches/16k/*.patch`, installs the custom Debian packaging, and writes the resulting `box86-16k_*_armhf.deb` to `dist/`.

You can also apply the series to a clean checkout manually:

```bash
./scripts/apply-box86-16k-patches.sh /path/to/box86
```

## Regression tests

Architecture-independent mapping model:

```bash
python3 tests/box86-16k/test_mapping_model.py
```

Synthetic ELF32 runtime test on the Pi 5:

```bash
getconf PAGESIZE
# expected: 16384

BOX86_BIN=box86-16k ./tests/box86-16k/test_16k_elfloader.sh
```

Expected success:

```text
BOX86_16K_ELF_OK
PASS: 4K-aligned ELF32 PT_LOAD segments execute on host page size 16384
```

Steam-specific regression:

```bash
BOX86_BIN=box86-16k ./tests/box86-16k/test_steam_16k.sh
```

The Steam test invokes `~/.local/share/Steam/ubuntu12_32/steam` directly through the selected Box86 binary, with rc files disabled and dynarec off, and fails if the pre-fix `0x309e9f8a / FF FF FF FF FF FF` signature appears.

## Installed package layout

```text
/usr/lib/box86-16k/bin/box86
/usr/bin/box86-16k
/usr/bin/steam16k
/usr/bin/box86-16k-status
/etc/binfmt.d/box86.conf
/usr/lib/box86-16k/tests/
```

The `steam16k` launcher deliberately does **not** unset `BOX86_NORCFILES` and does not force `BOX86_EMULATED_LIBS`, so strict isolation runs remain possible.

## Validation status

Patch syntax, shell syntax, the mapping-model test, and the generated ELF32 program headers were validated when this package was prepared. The final ARMHF build and 16K execution test must run on a Raspberry Pi 5 (or another ARM host with a 16K-page kernel).
